[2] SCORE COLUMN PATTERNS & PILLAR HYPOTHESES
──────────────────────────────────────────────

FxW (Function/Feature Weight) Mapping
  • Present in 59/60 rows (98%)
  • Distributed across all practice types
  • Highest in rows with:
    - Practice type = "Implement" (avg 24.19)
    - Output category = "Script" (avg 35.06)
    - Category - Entity = "TDD/BDD", "Test script" (avg 34-39)
  • Interpretation: FxW likely represents functional/feature implementation impact

GxW (Governance Weight) Mapping
  • Present in 54/60 rows (90%)
  • Concentrated in governance-related rows
  • Associated with:
    - Rows mentioning governance-related outputs (SRS, Checklist, Design, Release plan)
    - Governance-related roles (Architect, ITLead)
    - Governance-related tools (Jira, Confluence, ServiceNow)
  • Higher in "Manage", "Validate" practice types
  • Lower in "Implement" and infrastructure rows
  • Interpretation: GxW likely represents governance/control requirements

Correlation Analysis
  • Correlation coefficient: 0.8817 (strong positive correlation)
  • All 54 rows with GxW > 0 also have FxW > 0
  • 5 rows have FxW > 0 but GxW = 0 (non-governance functional tasks)
  • This suggests: GxW ⊆ FxW (governance is a subset of functional work)

[6] RECOMMENDED APPROACH FOR PILLAR GRAPH CONSTRUCTION
──────────────────────────────────────────────────────

Three strategies identified:

APPROACH A: Score Column Mapping (RECOMMENDED)
  ├─ Use: FxW and GxW as explicit pillar indicators
  ├─ Method:
  │  • For rows with GxW > 0: Link to Governance
  │  • For rows with FxW > 0 (and GxW = 0): Link to Function/Feature
  │  • All rows linked to Function (FxW universal coverage)
  │  • Use GxW > 0 as gate for Governance-specific relationships
  ├─ Pros:
  │  ✓ Objective, data-driven approach
  │  ✓ Clear threshold (non-zero value)
  │  ✓ No ambiguity in entity assignment
  │  ✓ Can assign multiple pillars per row (if needed)
  ├─ Cons:
  │  ✗ Only covers 2 of 9 pillars (Governance, Function)
  │  ✗ Other 7 pillars (Compliance, Security, Risk, etc.) unrepresented
  └─ Status: IMPLEMENTABLE NOW


APPROACH B: Text Category Mapping (PARTIAL)
  ├─ Use: Output category, Category - Entity, Practice type for implicit pillar hints
  ├─ Method:
  │  • "Plan/ design/ checklist" → Governance
  │  • "Script" + "Implement" → Function
  │  • Category containing "Test" → Quality
  │  • Category containing "Infra", "Environment" → Reliability
  ├─ Pros:
  │  ✓ Can derive multiple pillars per row
  │  ✓ Covers more pillars than approach A
  ├─ Cons:
  │  ✗ Heuristic-based, prone to false positives
  │  ✗ Requires careful rule-tuning
  │  ✗ Not data-validated
  └─ Status: REQUIRES MANUAL VALIDATION


APPROACH C: Lookup Table Mapping (BLOCKED)
  ├─ Use: Create explicit pillar-entity mappings in workbook
  ├─ Method: Add new column to Q_Stories listing pillar(s) per row
  ├─ Pros:
  │  ✓ Authoritative, maintainable
  │  ✓ Can map all 9 pillars
  ├─ Cons:
  │  ✗ Requires user to manually populate column
  │  ✗ Out of scope for current analysis
  └─ Status: REQUIRES EXTERNAL INPUT


RECOMMENDED HYBRID APPROACH
────────────────────────────
1. PRIMARY: Use score columns (Approach A)
   • Map GxW > 0 → Governance
   • Map FxW > 0 → Function/Feature
   • Use numeric values as relationship weights

2. SECONDARY: Text heuristics (Approach B, conservative)
   • Only apply heuristics where score columns don't cover
   • Example: Output category "Code" + practice "Engineer" → Quality/Function

3. PLACEHOLDER: Other pillars

   • Mark as "NOT MAPPED" in pillar graph nodes
   • Plan for future enhancement when workbook adds score columns for these pillars
